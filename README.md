# LLM Agent Skill Manager

조직원이 만든 Claude Code 스킬과 에이전트를 승인 절차를 거쳐 조직 자산으로 등재하고, 전 직원 PC에 자동으로 배포하고, 실제 사용량을 측정해 개선하거나 폐기하는 사내 스킬 관리 체계입니다.

## 왜 필요한가

- 같은 스킬을 팀마다 따로 만들고, 주인이 없어서 아무도 유지보수하지 않습니다.
- 스킬이 개인 PC에만 남아 있다가 퇴사나 이동과 함께 사라집니다.
- 스킬은 스크립트를 실행하고, 외부에서 가져온 스킬에는 프롬프트 인젝션이 섞일 수 있습니다. 그래서 스킬 등록은 코드 머지와 같은 수준으로 검토해야 합니다.

## 동작 흐름

```
① 제작  사내 작성 규칙으로 스킬 작성, eval 케이스 3건 이상 첨부
② 제출  "스킬 제출해줘" → 제출 전 점검 통과 시 접수 저장소에 PR 자동 생성
③ 검사  매시 재검사: 구조·메타데이터·권한·보안 스캔(SkillSpector, Cisco skill-scanner)
④ 검토  팀장이 업무 적합성 승인 → 자동 병합
        hook·MCP·scripts·쓰기 권한이 있거나 L2 라벨이 붙으면 승인자 보안 검토
⑤ 배포  Claude Code 조직 마켓플레이스로 전 직원에게 자동 반영
⑥ 측정  각 PC → OTel Collector → 주간 집계 → 사용량 대시보드
⑦ 개선  월간 eval 재실행으로 품질 하락 감지, 분기마다 미사용 스킬 폐기 검토
```

## 저장소 구성

| 경로 | 내용 |
|---|---|
| [`docs/PRD.md`](docs/PRD.md) | 요구사항 정의서. 경쟁 제품 9개 벤치마킹과 Claude Code 공식 문서 검증 결과를 담았습니다. |
| [`docs/IMPLEMENTATION-PLAN.md`](docs/IMPLEMENTATION-PLAN.md) | Phase 0~5 구현 계획 |
| [`catalog-skeleton/`](catalog-skeleton/) | 배포 카탈로그 골격. 마켓플레이스 정의, 팀별 플러그인 예시, CODEOWNERS, CI 워크플로, 구조 린트 스크립트 |
| [`skill-inbox/`](skill-inbox/) | 운영 중인 스킬 접수 저장소의 체계. 제출 방법, 팀장 검토와 L1/L2 보안 등급, 재검사 항목, PR 템플릿, 작성 규칙 스킬(`common-skill-guide`)과 제출 전 점검 스킬(`common-submit-skill`) |

`skill-inbox/`는 사내 저장소에서 접수 체계만 옮긴 공개본입니다. 직원이 제출한 스킬과 플러그인은 포함하지 않고, 조직명과 메일 도메인은 예시값(`example-org`, `example.com`)으로 바꿨습니다.

## 설계 원칙

- **네이티브 기능 우선:** 조직 마켓플레이스, 배포 등급(Required / Installed by default / Available), 서버 관리 설정은 Claude Code 기능을 그대로 씁니다. 직접 만드는 부분은 승인 파이프라인과 측정·개선 루프입니다.
- **접수와 배포 저장소 분리:** 작성자에게는 접수 저장소 쓰기 권한만 줍니다. 검사·병합·배포 워크플로와 비밀 값은 배포 저장소에만 둡니다.
- **스킬과 에이전트 구분:** 스킬은 `description`으로 자동 발동되지만 플러그인 에이전트는 자동 위임되지 않습니다. 비개발 직군이 자연어로 부르는 기능은 스킬로 만듭니다.
- **eval은 경고로만 사용:** LLM 호출이라 결과가 매번 달라질 수 있습니다. 머지를 막는 게이트로 쓰면 곧 우회되므로, 결과는 PR 코멘트로만 남깁니다.
- **민감 데이터는 스킬 밖에:** 단가, 심사 기준, 내부 정책은 MCP 서버나 사내 API 뒤에 두고, 스킬에는 절차만 적습니다.
