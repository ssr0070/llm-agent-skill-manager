## 1. 배경

스킬은 조직의 노하우를 실행 가능한 단위로 만든 자산이다. 지금은 거버넌스가 없다.

관찰된 실패 패턴:
- 같은 스택을 쓰는 팀들이 **같은 스킬을 각자 만든다**
- 주인이 없으니 **아무도 유지보수하지 않는다**
- 발견이 안 되니 **또 만든다**
- 개인 로컬 머신에만 남아 **퇴사·이동 시 사라진다**

여기에 보안 문제가 겹친다. 스킬은 결정론성을 위해 **스크립트를 실행**하고, 외부에서 가져온 스킬에는 **프롬프트 인젝션이 섞일 수 있다.** **스킬 등록은 코드 머지와 동급의 이벤트로 다뤄야 한다.**

**우리 조직의 특수 조건**: 개발자뿐 아니라 **영업·재무 직군이 이미 Claude Code를 사용 중**이다. 카탈로그의 첫 실사용 사례가 견적서 작성이며, 이는 설계 판단(자동 발동 필요, 민감 데이터 취급)에 직접 영향을 준다.

## 2. 목표 / 비목표

### 목표
- **G1** 조직원이 만든 스킬이 **승인 절차를 거쳐** 조직 자산이 되는 경로를 만든다
- **G2** 승인된 스킬이 **조직원 로컬 PC에 자동으로** 배포·갱신된다
- **G3** **어떤 스킬이 실제로 쓰이는지** 측정한다
- **G4** 측정 결과로 **스킬을 개선하거나 폐기**한다
- **G5** 위 전 과정이 **감사 가능**하다

### 비목표
- 타 에이전트(Cursor, Copilot, Codex) 지원
- **사내 CRM 앱 등 Claude Code 외부 런타임에서의 스킬 실행** — 별도 후속 과제
- 스킬 저작 GUI
- 사외 공개 마켓플레이스
- 스킬 자동 진화 — **거버넌스가 먼저다.** 가드레일 없는 자동 진화는 문제를 증폭시킨 채 자동 유지보수한다

## 3. 성공 지표

> v1.0의 지표는 수백 명 조직 기준이었다. 50명 미만·관리자 3명 기준으로 재설정한다.

| 지표 | 방향 | 현재 | 3개월 | 6개월 |
|---|---|---|---|---|
| 카탈로그 등재 스킬 수 | ↑ | 미측정 | 12 | 25 |
| **스킬을 1회 이상 사용한 조직원 비율(채택률)** | ↑ | 미측정 | 기준선 확보 | 50% |
| 오너 지정률 | ↑ | 0% | 100% | 100% |
| 중복 스킬 | ↓ | 미측정 | 측정 | **0건** |
| 신규 입사자 스킬 셋업 시간 | ↓ | 반나절+ | 10분 | 0분(자동) |
| 승인 리드타임(제출→게시) | ↓ | N/A | < 3영업일 | < 1영업일 |
| 미사용 스킬(30일 0회) 비율 | ↓ | N/A | 측정 | < 20% |

**삭제된 지표**: "스킬 호출 수 3배" — 폐기(FR-702)를 잘할수록 내려가 G4와 충돌하고, 오발동해도 오르므로 `description`을 과하게 넓게 쓰라는 잘못된 인센티브를 만든다. **채택률로 대체.**

**G0 (선행)**: 지표를 재기 전에 **가시성부터 확보한다.** 조직에 스킬이 몇 개 흩어져 있는지 모르면 나머지는 전부 추측이다. Phase 0의 유일한 목표다.

## 4. 벤치마킹 요약

9개 제품을 10개 축으로 비교했다. 설계 판단에 직접 영향을 준 결론만 옮긴다.

| 발견 | 설계 함의 |
|---|---|
| Claude Code가 이미 조직 마켓플레이스, 배포 등급, 정책 강제, **서버 관리 설정**을 갖고 있다 | 직접 만들 이유가 없다. 골격은 네이티브로 간다 |
| JFrog의 "approval workflow"는 실제로는 Xray 보안 스캔이다 | 상용 제품의 "승인"을 그대로 믿으면 안 된다. 사람 승인은 우리가 붙여야 한다 |
| 사람 승인 게이트가 진짜 있는 곳은 Credal·Google·iflytek/skillhub뿐 | **git PR 리뷰가 가장 현실적인 승인 게이트다** |
| **GBrain(OSS)이 skillpack 레지스트리·무결성 검증·endorse·trust prompt를 한 저장소에서 구현하고 있다** | v1.0의 "레지스트리+무결성 공백" 주장은 과했다. **레퍼런스 구현으로 참고**한다 |
| 사용 시점 자동 갱신 제품은 없다 | 다만 Claude Code의 세션 시작 자동 갱신으로 실무 요구의 대부분이 해결된다 |
| **스킬별 사용량을 조직 단위로 보여주는 경로가 어떤 플랜에도 없다** | **새로 확인된 공백.** OTel 자체 수집이 유일한 경로다 |
| 사용량→평가→개선 루프를 닫은 제품은 없다 | 우리가 만들면 차별점. 자동화가 아니라 **정기 배치 + 사람 판단**으로 시작 |
| 이 시장에 투자 유치 스타트업도, 한국 기업도 없다 | 외부 조달 옵션이 사실상 없다. 자체 구축이 합리적이다 |

## 5. 방안 선정

### 5.1 세 가지 안

|  | **A안 (채택)**<br>네이티브 골격 | **B안**<br>훅 기반 자체 레지스트리 | **C안**<br>기성 레지스트리 도입 |
|---|---|---|---|
| 배포 골격 | Claude Code 조직 마켓플레이스 | 사내 git + 자체 훅 | skillhub 셀프호스팅 |
| 승인 | git PR + CODEOWNERS + CI | git PR + CI | 제품 내장 승인 UI |
| 로컬 갱신 | 세션 시작 자동 | 훅이 전담 | CLI 수동 |
| 강제 배포 | **가능** (Required 등급) | 사실상 가능 | 불가 |
| 플랜 요건 | **Teams/Enterprise 필요** ✅ 보유 | 불필요 | 불필요 |
| 구축 공수 | **중 (7주)** | 대 (8~12주) | 소~중 (3~4주) |
| 깨질 위험 | 낮음 | **매우 높음 — 문서 검증으로 확정** | 중 |

### 5.2 선정: **A안**

**근거 3가지.**

1. **직접 만들 부분이 가장 적다.** 카탈로그·배포 등급·정책 강제가 전부 네이티브로 존재한다. 우리가 만들 건 승인 파이프라인과 측정·개선 루프뿐이다.
2. **강제 배포가 되는 유일한 경로다.** `Required` 등급은 자동 설치 + 사용자 제거 불가다. 보안·컴플라이언스 스킬에 반드시 필요하다.
3. **B안이 문서 검증으로 탈락했다.** v1.0은 "미문서 스키마 의존" 우려로 B안을 후순위에 뒀는데, 검증 결과 우려가 사실로 확인됐다 — `reloadSkills` 훅 출력 필드는 **존재하지 않고**, 슬래시 커맨드 스킬 호출은 `PreToolUse`를 **발동시키지 않는다**. §12 참조.

**A안이 포기하는 것**: "사용자가 호출하는 그 순간" 갱신. 대신 **세션 시작 시점** 갱신(최대 10분 랜덤 지연)이다. 실무 영향은 작다.

**폴백**: A안 불가 시 **C안**(skillhub 셀프호스팅). ~~B안~~은 폴백 자격을 잃었다.

### 6.2 저장소 구조

단일 저장소, **GitHub.com 조직 계정**. 팀별 폴더 소유가 핵심이다.

```
acme-skills/
├── .claude-plugin/marketplace.json
├── plugins/
│   ├── common/          # Required 등급. 오너: 시큐리티 리드
│   ├── platform/        # 오너: 엔지니어링
│   ├── sales/           # 견적 관련. 오너: 엔지니어링
│   └── finance/
├── .github/
│   ├── CODEOWNERS               # 플러그인 디렉터리 단위 = 오너 강제 장치
│   ├── PULL_REQUEST_TEMPLATE.md
│   └── workflows/skill-ci.yml
├── scripts/
│   ├── lint_structure.py        # 구조 린트 + 위험도 판정
│   └── inventory.sh             # Phase 0 자가진단
└── docs/CONTRIBUTING.md
```

**CODEOWNERS가 "이름 없는 스킬은 죽은 스킬" 문제를 구조적으로 막는다.** 오너가 없으면 PR이 머지되지 않는다.

### 6.3 스킬과 에이전트의 구분 — **설계 핵심**

문서 검증으로 확인된 결정적 차이다.

|  | 자동 발동 | 호출 방법 | 컨텍스트 비용 |
|---|---|---|---|
| **스킬** | ✅ 됨 | `description`을 모델이 매 턴 읽고 판단 | 목록이 **1% 예산** 소비, 항목당 1,536자 상한 |
| **플러그인 에이전트** | ❌ **안 됨** | `@plugin:agent` 로 직접 지목 | **없음** (호출 시에만 로드) |

에이전트의 `description`은 **정보 표시용일 뿐 자동 위임을 유발하지 않는다.**

**따라서 배치 규칙:**
- **자동 발동이 필요하면 → 스킬.** 비개발 직군이 자연어로 부르는 모든 기능(견적서 포함)
- **긴 자율 작업을 별도 컨텍스트에서 돌려야 하면 → 에이전트.** 사용자가 명시적으로 지목

### 6.4 단계별 사양

#### ① 제작 (FR-100)
- **FR-101** 사내 `skill-creator` 스킬 배포. 템플릿·네이밍·필수 frontmatter 강제
  - **1번 규칙: 민감 데이터를 SKILL.md 본문에 넣지 않는다.** 단가·심사 기준·내부 정책은 MCP 서버나 사내 API 뒤에 두고, 스킬에는 **절차만** 적는다
  - `description`은 자동 발동의 유일한 근거다. **1,536자 이내**, 언제 쓰는지를 구체적으로 적는다
- **FR-102** `evals/cases.jsonl` 생성을 제출 요건으로 포함. **점수로 막지는 않는다**
- **FR-103** 평가 케이스 최소 3개 — trigger / non-trigger / edge case

#### ② 제출 (FR-200)
- **FR-201** `/skill-submit <name>` — 브랜치 생성 → PR 생성 자동화. **전 직군 git 사용**
- **FR-202** PR 템플릿 필수 기입: **오너**, **배포 등급**, 목적, **중복 검토 결과**, **다루는 데이터 등급**
- ~~FR-203 자동 중복 유사도 검색~~ → **Phase 5 이후.** 25개 미만 카탈로그는 사람이 목록을 훑는 편이 빠르고 정확하다

#### ③ 심사 (FR-300)
- **FR-301 스크립트 검사(하드 게이트)**: 번들 스크립트 정적 분석 — 네트워크 호출, 파일 쓰기, 셸 실행, 시크릿 접근
- **FR-302 프롬프트 인젝션 검사(하드 게이트)**: SKILL.md 본문의 지시 무시, 권한 상승, 외부 URL 유도 패턴
- **FR-303 eval(경고)**: `evals/cases.jsonl` 실행 결과를 PR 코멘트로 게시. **머지를 막지 않는다** — LLM 호출이라 비결정론적이고, 랜덤하게 빨간불이 뜨는 게이트는 곧 우회된다
- **FR-304 위험도 자동 판정**: 아래 중 **하나라도** 해당하면 사람 승인, 아니면 자동 승인
  - `scripts/` · `hooks/` · `.mcp.json` · `bin/` 디렉터리·파일 존재
  - 에이전트 frontmatter의 `tools`에 `Bash` 또는 `Write` 포함
  - 에이전트에 `tools` 미명시 (→ 무조건 사람 승인)
- **FR-305 오너 지정**: CODEOWNERS 등재 없이는 머지 불가
- **FR-306** CI 2종 통과 + (위험 시) 오너 1인 승인으로 머지. 브랜치 보호 규칙으로 강제

#### ④ 게시 (FR-400)
- **FR-401** 머지 시 조직 마켓플레이스 동기화. **동기화 트리거는 Phase 1 실측 대상**(§11-1)
- **FR-402** 플러그인 소스는 커밋 SHA로 핀한다. **정확한 문법은 Phase 1 실측 대상**(§11-3)
- **FR-403** 배포 등급 매핑

| 접근 등급 | 조직 설정 등급 | 동작 |
|---|---|---|
| 보안·컴플라이언스 필수 (`common`) | **Required** | 자동 설치, 제거 불가 |
| 전사 공통 | **Installed by default** | 자동 설치, 제거 가능 |
| 팀 한정 | **Available for install** | 검색·수동 설치 |

> ~~restricted 등급~~ **삭제.** 그룹별 노출 제한은 **Teams·Enterprise 모두 불가**하다 (§12). 민감 정보 보호는 FR-101 1번 규칙(데이터를 스킬 밖으로)으로 달성한다.

#### ⑤ 로컬 배포·갱신 (FR-500)
- **FR-501** **서버 관리 설정** 사용. claude.ai 관리자 콘솔 → Claude Code → Managed settings. **MDM 불필요**
- **FR-502** 조직 마켓플레이스는 관리자 콘솔 → Plugins에서 등록. **등록 경로와 자동 갱신 기본값은 Phase 1 실측 대상**(§11-1)
- **FR-503** `strictKnownMarketplaces`로 허용 소스를 제한한다. **빈 배열로 두지 않는다**
- ~~FR-504 폐쇄망 hostPattern~~ → 해당 없음 (GitHub.com 사용)
- ~~FR-505 훅 기반 즉시 갱신~~ → **삭제** (§12)

> **알려진 동작**: 자동 갱신은 세션 시작 후 **최대 10분 랜덤 지연** 백그라운드로 수행된다. **실행 중인 세션은 시작 시점 버전을 계속 쓴다** — 갱신 알림이 뜨면 `/reload-plugins`, 아니면 다음 세션에 자동 반영. 이 동작을 사용자에게 사전 공지한다.

#### ⑥ 측정 (FR-600)
- ~~FR-601 Admin Analytics API~~ → **삭제.** Enterprise 전용 (§12)
- **FR-602 OTel 수집**: 각 PC → 사내 OTel Collector → 파일/SQLite → 주간 집계

| 메트릭 | 사용 속성 |
|---|---|
| `claude_code.token.usage` | `skill.name`, `plugin.name`, `agent.name`, `marketplace.name` |
| `claude_code.cost.usage` | 동일 (스킬별 비용) |
| `claude_code.lines_of_code.count` | `skill.name`, `plugin.name` |

- **FR-603 `OTEL_LOG_TOOL_DETAILS=1`**: 켜지 않으면 사내 스킬 이름이 `"custom"`/`"third-party"`로 마스킹되어 **스킬별 집계가 불가능**하다. **전사 적용하되 사전 공지 필수** (§11-4)
- **FR-604 대시보드**: 주 1회 집계 → **정적 HTML 1장**. 3개 뷰
  1. 호출 상위 스킬
  2. **30일 0회 스킬** (폐기 후보)
  3. 플러그인(팀)별 사용량 + 스킬별 토큰 비용
- **FR-605 보조**: claude.ai 관리자 대시보드 CSV를 월 1회 내보내 전체 채택률 확인
- ~~자동 발동 vs 수동 호출 비율~~ → **삭제.** `invocation_trigger` 속성이 존재하지 않는다

> **측정할 수 없는 것(확정)**: 누가 어떤 플러그인을 **설치**했는지, Required 플러그인의 **도달률**. Teams에 조회 경로가 없다. **"설치됐다"가 아니라 "쓰였다"를 배포 성공의 증거로 삼는다.**

#### ⑦ 개선 (FR-700)
- **FR-701 월간 배치**: 상위 스킬 eval 재실행. 점수 하락 시 오너에게 이슈 자동 생성
- **FR-702 분기 폐기 리뷰**: 90일 0회 스킬을 오너에게 통보, 2주 무응답 시 deprecated
- **FR-703 모델 릴리스 대응**: 새 모델 출시 시 전체 스킬 eval 재실행을 필수 이벤트로 등록
- **FR-704** 자동 개선은 하지 않는다. 배치는 **후보를 제시**하고, 판단과 수정은 오너가 한다

### 6.5 거버넌스 조직

기술로 해결되지 않는 부분이다. 관리자 3명 기준 **3역할**로 재편한다.

| 역할 | 인원 | 승인 대상 |
|---|---|---|
| 엔지니어링 오너 A | 1 | `platform` — 개발 워크플로·인프라 스킬 |
| 엔지니어링 오너 B | 1 | `sales`, `finance` — 업무 스킬 |
| **시큐리티 리드** | 1 | **`common`(Required) + 전 스킬의 스크립트·권한 검토** |

FR-304의 자동 승인 덕분에 **문서형 스킬은 승인 대기열에 들어오지 않는다.** 3명이 실제로 봐야 할 것은 스크립트·MCP·훅을 포함한 소수다.

## 7. 비기능 요구사항

- **NFR-1 가용성**: 사내 git이나 마켓플레이스 장애가 개발자 세션을 중단시켜서는 안 된다. 동기화 실패 시 **기존 캐시로 조용히 폴백**한다
- **NFR-2 성능**: 배포·측정 계층이 세션 시작을 1초 이상 지연시키지 않는다
- **NFR-3 감사**: 제출·승인·게시·등급 변경 전부 git 이력에 남는다
- **NFR-4 컨텍스트 예산**: 스킬 목록은 컨텍스트 윈도우의 **1%**를 쓰고, **항목당 1,536자 상한**이 있다. 초과 시 **호출 빈도가 낮은 스킬부터 description이 잘려** 매칭이 실패한다.
  - `skillListingBudgetFraction` / `skillListingMaxDescChars`로 조정 가능하나, **기본 1%를 유지**한다 — 상향은 모든 세션의 모든 요청에 항구적 토큰 비용을 얹는 결정이다
  - Phase 1에서 **"스킬 몇 개부터 잘리기 시작하는가"를 실측**해 전사 배포 상한을 정한다
  - **에이전트는 이 예산을 소비하지 않는다** (호출 시에만 로드)
- **NFR-5 오프라인**: 네트워크 없이도 마지막 동기화 상태로 정상 동작한다

## 8. 보안 요구사항

- **SEC-1** 플러그인 소스는 커밋 SHA로 핀한다 (FR-402)
- **SEC-2** 외부 공개 마켓플레이스는 `strictKnownMarketplaces`로 차단. 도입 시 사내 저장소로 rehosting 후 동일 심사
- **SEC-3** 훅 스크립트는 사용자 전체 권한으로 실행된다. 훅을 포함한 플러그인은 **무조건 사람 승인**(FR-304)
- **SEC-4** **민감 데이터는 스킬 본문에 넣지 않는다.** 그룹별 노출 제한이 플랫폼에 존재하지 않으므로, 카탈로그 등재 = 전사 공개다. 단가·심사 기준·내부 정책은 MCP/API 뒤에 둔다
- **SEC-5** 개인 GitHub 계정에서 테스트할 때는 **더미 데이터만** 사용한다. 사내 팀명·업무 절차·견적 관련 내용을 개인 저장소에 두지 않는다
- **SEC-6** 비공개 플러그인 소스는 마켓플레이스 저장소와 **같은 GitHub 소유자**여야 한다. 플러그인을 별도 저장소로 분리하더라도 전부 같은 조직 아래 둔다

## 9. 로드맵 (7주)

| Phase | 기간 | 산출물 | 완료 기준 |
|---|---|---|---|
| **0. 가시성** | 2~3일 | 자가진단 스크립트, 스킬 인벤토리 | 파일럿 팀 100% + 전체 60% 응답 |
| **1. 골격** | 2주 | 저장소, marketplace.json, 4개 플러그인, CODEOWNERS | 파일럿 팀 설치 성공 **+ 갱신 도달 확인** + §11 실측 5건 |
| **2. 게이트** | 1.5주 | CI 2종, 위험도 판정, PR 템플릿, `/skill-submit` | 외부 기여 PR이 게이트를 거쳐 머지됨 |
| **3. 배포** | 0.5주 | 서버 관리 설정, 등급 매핑 | 신규 입사자 0분 셋업 |
| **4. 측정** | 3~4일 | OTel Collector, env 배포, 주간 집계 + 정적 HTML | 스킬별 사용량 1회 산출 |
| **5. 개선 루프** | 2주 | 월간 eval 배치, 폐기 리뷰 프로세스 | 첫 폐기 결정 1건 실행 |

**Phase 0~3이 MVP다. 약 4.5주.** 전체 7주, 마감(11/10) 대비 여유 1주.

## 10. 리스크

| 리스크 | 영향 | 대응 |
|---|---|---|
| **조직 마켓플레이스 자동 갱신이 기본 off** | 아무도 갱신을 못 받는데 아무도 모른다 | **Phase 1 완료 기준에 "갱신 도달 확인"을 명시** |
| **스킬별 배포 현황 조회 불가** | 배포 성공 여부를 직접 확인 못 함 | "쓰였는가"를 대리 지표로 사용 |
| 스킬 목록 예산 초과 | description 잘림 → 매칭 실패 | Phase 1 실측으로 상한 확정, 초과 시 팀별 배포 |
| eval 케이스 작성 부담으로 제출 기피 | 카탈로그가 안 큰다 | 템플릿 자동 생성, **점수로 막지 않음** |
| 승인 병목 (관리자 3명) | 리드타임 증가 | **문서형 스킬 자동 승인**(FR-304)으로 대기열 축소 |
| 비개발 직군의 git 학습 부담 | 제출 감소 | `/skill-submit`이 전 과정을 감춤. 실패 시 관리자 대리 제출로 폴백 |
| `OTEL_LOG_TOOL_DETAILS` 동의 미확보 | 스킬별 측정 불가 → Phase 5 무력화 | Phase 4 이전에 동의 절차 완료 (§11-4) |
| **개인 저장소에 사내 정보 유출** | 공개 설정 실수 시 노출 | SEC-5 — 더미 데이터만 사용 |

## 11. 미해결 질문

1. **조직 마켓플레이스 등록 경로와 자동 갱신 기본값** — 관리자 콘솔인지 `extraKnownMarketplaces` 설정인지 문서상 엇갈린다. **Phase 1 실측** (FR-401, FR-502)
2. **동기화 트리거** — `plugin.json` version bump인지 임의 커밋인지 미문서. **Phase 1 실측**
3. **커밋 SHA 핀 문법** — 브랜치·태그(`#<ref>`)는 확인, 임의 SHA는 미문서. **Phase 1 실측** (FR-402)
4. **`OTEL_LOG_TOOL_DETAILS=1` 조직 동의** — 직원 툴 사용 상세가 사내에 수집된다. **승인 주체를 정하고 사전 공지할 것.** Phase 4 선행 조건
5. **에이전트에 배포 등급이 스킬과 동일하게 적용되는가** — 미문서. Phase 1 실측
6. **OTel Collector 호스팅 위치** — 사내 서버 지정 필요. Phase 4 선행 조건
7. **Claude Code 버전 하한** — 일부 env 전달에 v2.1.198 이상이 필요하다는 언급. Phase 3에서 조직 내 버전 분포 확인
8. **저장소 이름** — 본 문서는 `acme-skills`를 임시 사용

## 12. v1.0에서 삭제·수정된 조항과 근거

모두 **Claude Code 공식 문서 검증**으로 확인했다.

| v1.0 조항 | 조치 | 근거 |
|---|---|---|
| FR-501 MDM 파일 배포 | **삭제** | 서버 관리 설정으로 관리자 콘솔에서 배포 가능. MDM 불필요 |
| FR-502 `extraKnownMarketplaces` + `autoUpdate` | **재작성** | 해당 설정은 서버 관리 범위 밖(User/Project/Local). 조직 마켓플레이스는 별도 경로 |
| **FR-505 `reloadSkills: true` 훅** | **삭제** | **해당 훅 출력 필드가 존재하지 않는다.** 훅 출력은 `systemMessage`/`terminalSequence`/`hookSpecificOutput` |
| **FR-601 Admin Analytics API** | **삭제** | **Enterprise 전용.** Teams는 관리자 대시보드 + CSV만 |
| **FR-602 `claude_code.skill_activated` 이벤트** | **삭제** | **해당 이벤트가 존재하지 않는다.** `token.usage`/`cost.usage`의 `skill.name` 속성으로 대체 |
| FR-604 자동발동/수동 비율 | **삭제** | `invocation_trigger` 속성 부재 |
| **SEC-4 `restricted` 등급** | **재작성** | **그룹별 노출 제한은 Teams·Enterprise 모두 불가.** "설정은 모든 사용자에게 균일 적용되며 그룹별 구성은 미지원" |
| 부록A 실험4 슬래시 경로 커버 | **결론 확정(불가)** | 슬래시 커맨드 스킬 호출은 `PreToolUse`를 발동시키지 않는다. `UserPromptExpansion` 단계에서 확장 |
| 견적서를 **에이전트**로 구현 | **스킬로 전환** | **플러그인 에이전트는 자동 위임되지 않는다.** `@plugin:agent` 수동 호출 필요 |
| FR-203 자동 중복 검색 | **연기** | 25개 미만 카탈로그에 과잉 |
| FR-303 eval 하드 게이트 | **경고로 완화** | LLM 호출은 비결정론적. 랜덤 실패하는 게이트는 우회된다 |
| 오너 4역할 | **3역할로** | 관리자 3명 |
| §3 지표 (80개 / 호출 3배) | **하향·교체** | 50명 미만 규모 |
| 벤치마킹 8종 | **9종으로** | GBrain 추가 |

**A안 골격은 검증 후에도 유지된다.** 배포 등급 4종, 서버 관리 설정, managed-settings 3개 OS 경로, 세션 시작 후 최대 10분 지연, 컨텍스트 1% 예산과 1,536자 상한은 모두 **문서로 확인**됐다.
